## 2. Chosen data owner

Course-page data lives **inline in the page frontmatter** at `src/opetus/teknologiatuettu-oppiminen-2026-a.md` under a single `course:` object (courseId, courseName, credits, period, academicYear, peppiUrl, teachingUnitLabel, lectures[], thesisTeaser). No new `src/_data/coursePages.js` global data owner was created — per §6, this is a single-course bounded feature, not a "generalized semester/course engine".

Presentation hydration happens in a thin adapter at `src/opetus/teknologiatuettu-oppiminen-2026-a.11tydata.js` (34 LOC) that resolves lecture `presentationPageUrl` values against `buildCanonicalPresentationPageLookup(data)`. This adapter reuses the existing canonical Presentation pipeline; it does not build a second reader.

`src/_data/teachingUnits.js` gained one line: `"405040Y": OK` (Opettajankoulutus). This makes `courseContexts.courseId === "405040Y"` produce the correct `teachingUnit` / `teachingUnitLabel` on new Presentation landings via the existing `eleventyComputed` cascade in `src/presentations/presentations.11tydata.js`.

## 3. Final data flow

```
course-page frontmatter (course.lectures[].presentationPageUrl)
        +

        +

        +

        ↓

        ↓
complete SSR HTML at /opetus/teknologiatuettu-oppiminen/2026-a/
```

No page-specific JavaScript. No runtime JSON. No SPA.
