## 3. Current Pagefind capabilities on presentations

Two producers of presentation Pagefind data currently exist:

### Producer 1 — Eleventy computed (PF5-G2, merged 2026-08-24)

- `src/src.11tydata.js` `resolvePagefindPresentations(data)` at line 196.
- Runs at build time via `eleventyComputed`.
- Emits per-page filters and meta into presentation detail HTML.
- Scope: **local-first only.** Lookup by `data.page.url` against `pageUrl` and `localPageUrl` of enriched canonical items. External-first records have no local page URL and cannot match.
- Emitted filters: `Sisältö:Esitykset`, `FindExplore:presentations`, `PresentationYear`, `PresentationType`, `PresentationTopic` (up to 6), `Research context:research`.
- Emitted meta: `PresentationYear`, `PresentationType`, `PresentationEvent`.
- Missing: `data-pagefind-sort="date:..."`.
- Measured coverage per G2 doc: **135 pages** (local-first). Research-context subset: 33.

### Producer 2 — Postbuild custom records (`scripts/run-pagefind.js`)

- Present at `scripts/run-pagefind.js:103`: `index.addCustomRecord(buildPresentationCustomRecord(record, content))`.
- Invoked once per canonical item that has **no** local HTML index candidate (i.e., external-first with no representation page).
- `scripts/_lib/presentationPagefind.js:buildPresentationCustomRecord`:
  - `url: record.preferredLandingUrl` → the canonical landing URL (which for external-first is the external URL, e.g., Canva `sourceUrl`).
  - `language: record.pagefindLanguage` (fi/en heuristic).
  - `content`: title, description, HTML-extracted body (from a local alternate representation if available), event, type, role, contexts, topics, research preset labels.

## 5. Local-first / external-first suitability

This is the critical semantic gate.

### Current SSR archive (all 218 rendered by `result-card.njk`)

Per `src/_includes/presentations/result-card.njk`:

- `cardUrl = item.landingUrl or item.localPageUrl or item.pageUrl or item.url or item.externalUrl or item.sourceUrl or ""`
- `cardIsExternal = item.externalFirst or (cardUrl and cardUrl.startsWith("http"))`
- External cards render with `target="_blank" rel="noopener noreferrer"` and `bi-arrow-up-right` glyph.
- External badge label: FI "Ulkoinen" / EN "External".
- Local badge label: FI "Paikallinen sivu" / EN "Local page".

### Current bespoke JS card (`archiveCardHtml`)

Per `src/js/presentations-page.js:133`:

- Same `landingUrl → externalUrl` fallback chain.
- Adds `returnTo=<current URL>` decoration when target is `/presentations/...` and not external. Confirms O1 orientation semantics on discovery-return.
- Same external target / rel behavior.
- Same badge behavior.

### Pagefind + shared presenter

Per `src/js/search-result-presenter.js:renderSharedCard`:

- Title link: `<a class="find-explore-result-title" href="${escapeHtml(entry.url)}">`.
- `entry.url = data?.url || ""` from `projectEntry`.
- **No** `target="_blank"` / `rel="noopener"` decoration.
- **No** external/local badge — only the family badge ("Esitykset").
- **No** returnTo decoration.

### Consequence per source type

1. Missing external target attributes (§5).
2. Missing external/local badge (a canonical semantic signal — "this opens Canva").
3. Missing source label chip ("Canva", "SlideShare", "YouTube", "AOE") — semantic loss of provider identity.
4. Missing topic chips on the card — F&E currently uses topics only as facets.

Visual differences alone (1 vs 3 topic chips, badge shape, etc.) are not
semantic blockers. Items 1–3, 5, and 7 are semantic — they either change
where the click goes or lose canonical provider identity.

## 8. Index suitability

Post-PF5-G2 + hotfix state:

- `data-pagefind-body` scope on `<main>` in `base.njk` (site-wide, per hotfix `4b3ba2f7`).
- `data-pagefind-ignore` on chrome regions in `presentation-item.njk`.
- Presentation detail records carry `Presentation*` attribute-form filters + meta from PF5-G2.
- Presentation detail records ALSO receive a hidden `<div data-pagefind-ignore="all">` from `presentationPagefind.js:injectPresentationPagefindMetadata` during postbuild. Because the wrapper is `data-pagefind-ignore="all"`, Pagefind ignores the div's text but still reads `data-pagefind-filter` / `data-pagefind-meta` spans inside. This overlaps with PF5-G2's Eleventy projection.
- Custom records for external-first: emit `Sisältö:Esitykset` + full filter/meta bundle with `url = preferredLandingUrl` (may be external HTTPS URL).

### Concerns

- **Duplication.** PF5-G2 and `presentationPagefind.js` both write attribute-form filter/meta for local-first records. Whether Pagefind deduplicates identical `data-pagefind-filter="Sisältö:Esitykset"` occurrences per page is not documented locally; if it does not, facet counts could double-count. Not observed as a live issue in G2 build evidence (135 pages reported), but should be reconciled before further reliance.
- **Custom-record excerpt quality.** External-first custom records use `resolveCustomRecordContent()` which reads text from a local representation HTML file when available, else empty content. Pagefind excerpts for external-first records with no local representation will be title-only. Acceptable for facet-based discovery, weaker for free-text.
- **`data-pagefind-sort="date:...":`** not emitted by PF5-G2 for presentations; media has it. Sort by date across Pagefind results is unavailable without adding it.
- **URL semantics in custom records.** `preferredLandingUrl` from `presentationPagefind.js` can be a fully-qualified external HTTPS URL. Pagefind indexes the URL as-is. Confirming Pagefind is happy with non-`/`-rooted URLs is a build-time verification, not answered here.
- **`getFromEleventy` no-ops for `presentationType`, `event`, and `topics`.** In `contentPresets.js:159, 173, 128`, these fields return `null` / `[]` when queried from Eleventy items. The Node-side preset cannot filter on them at build time. The browser-side preset (over normalized JSON records) can. The migration to shared Pagefind bypasses this constraint but ties archive filtering to Pagefind's facet vocabulary.

- Same 12 SSR archive cards visible IF the SSR archive shell is preserved.

### Shared Pagefind runtime (Pagefind module load failure)

- `find-explore.js:createSearch` throws; per line 1139 catch, "FindExplore search failed" is logged.
- The F&E mount typically shows an error text.
- If SSR opening set is preserved, the archive is still browsable in its opening form.

### Regression risk

The current no-JS user gets a curated view of 12 cards + 4 SSR source
sections + working navigation. Any migration must preserve this floor.
`find-explore.js` mounts on other archives typically do preserve SSR
opening content, but per-mount configuration matters. The audit finds no
inherent Pagefind-side reason no-JS behavior would regress — but the
migration package must include an explicit assertion.

## 12. Architecture decision

**D — HYBRID IS THE CORRECT TARGET.**

Reasoning:

- **External-first records (80 of 218) require external landing semantics.** The current shared presenter renders every title link as a same-tab internal-looking `<a>` with no `target="_blank"` / `rel="noopener"` / external badge (§5, §7). Migrating archive discovery to the shared presenter as-is would silently open external URLs in-tab and remove the "Ulkoinen / External" affordance. This is a semantic regression, not a visual polish item.
- **Pagefind facet vocabulary is not yet a superset of the current interaction.** `data-pagefind-sort="date:..."` is not emitted (§8, §6). Topic filtering with 406 options is not a natural F&E chip UI. Both are solvable but require prerequisite work.
- **Custom-record coverage for external-first exists in the pipeline** (`scripts/run-pagefind.js:103` + `scripts/_lib/presentationPagefind.js:buildPresentationCustomRecord`) but **live coverage is not verified in this audit.** A future FULL Pagefind decision requires that verification and the presenter hardening above.
- **Duplication between PF5-G2 Eleventy projection and `presentationPagefind.js` postbuild injection (§3, §8)** should be reconciled before further reliance on any single path.
- **The immediate deletable code is the archive card renderer.** `archiveCardHtml()` (~54 LOC) duplicates `result-card.njk` and adds only two behaviors the SSR partial lacks: description truncation to 180 chars, and `returnTo` decoration for local `/presentations/...` destinations. Both can be moved into the SSR partial in a small, verifiable change that requires no Pagefind decision.

Under Decision D:

- **SSR and canonical archive remain authoritative** for the 218-item archive. All external-first records stay discoverable via the current SSR + client filter/search path.
- **Pagefind and shared presenter remain authoritative** for global discovery (`/haku/`, `/en/search/`, navbar), where local-first presentations already appear correctly with the shared card since PF5-G2, and external-first are outside the shared-card path by design.
- **Slice 3 (template unification)** consolidates the archive card path onto `result-card.njk` and removes `archiveCardHtml()`. The shared presenter is not adopted on `/esitykset/` — that decision is deferred until the prerequisites for Decision B are validated in a separate audit.

Decision D preserves canonical/source/landing semantics under all
current interaction modes and unlocks a bounded, low-risk deletion now.
Decision A/B remain viable long-term targets but require prerequisites
this audit cannot fully verify.

### What would move the decision to B

The following, in order, would justify reopening this decision as
`B — SUITABLE AFTER SMALL PREREQUISITES`:

1. Verified live custom-record coverage for external-first presentations (build + Pagefind API query).
2. Reconciliation of PF5-G2 Eleventy projection vs `presentationPagefind.js` postbuild injection (choose one owner, delete the other).
3. Shared presenter enhancement to distinguish external / local URLs: `target="_blank" rel="noopener noreferrer"` on external, plus the external-source badge.
4. Emit `data-pagefind-sort="date:..."` from `resolvePagefindPresentations`.
5. Design decision on the topic combobox (406 topics vs F&E chip UI).
6. Design decision on returnTo semantics under Pagefind: does F&E rewrite title-link hrefs for local destinations?

These are not blockers to Slice 3; they are prerequisites to a FULL
migration audit.
