# R1-ADR1 — Semantic Related-Content Architecture Decision

Date: 2026-08-29

## Status

`ACCEPTED` — pending merge of the docs-only PR that carries this ADR and the roadmap sync update.

## Context

R1 (canonical related-content projection) is post-closure work per `docs/site-architecture-closure-roadmap-2026-08-20.md` §4. The R1-A suitability audit (2026-08-29, on `main` at `274afe0d`) discovered that the target architecture is already implemented via the `computeRelatedContent` Eleventy filter + `content-context-sidebar.njk` on five detail templates. It also observed that `computeRelatedContent` currently combines two contributions:

1. **Deterministic canonical metadata score** — categories × 5, keywords × 3, contexts × 4, tags × 2, type × 2.
2. **Additive semantic-similarity boost** — `SEM_WEIGHT = 5` applied when the pair-wise cosine similarity from `src/_data/semanticRelated.json` reaches `SEM_MIN = 0.6`.

The semantic layer is generated by `scripts/build-semantic-related.js` from a PR-#77 embedding cache. It was authored during pre-closure v4.4 work, well before the 2026-08-20 roadmap articulated the R1 hard boundary "no embedding / LLM recommender".

R1-B1 (add the shared related-content sidebar to `src/opinnaytteet/thesis-details.njk`) was proposed as the smallest surface-coverage next slice by R1-A. R1-A itself blocked R1-B1 pending an explicit ADR because extending the current filter to a new template would extend the embedding contribution to that template. That is the boundary conflict this ADR resolves.

R1-B0 (2026-08-29, `docs/r1b0-semantic-related-content-reconciliation-audit-2026-08-29.md`, on `main` at `f944c362`) measured the removal cost via a deterministic ablation over 50 deterministic samples (10 per consuming domain: Publications, Presentations, Media, Blog, Writings), running `computeRelatedContent` unchanged twice per source item with `semanticRelated = production` and `semanticRelated = {}`. Its decision was **B — Semantic layer materially useful but conflicts with current R1 contract**, and it escalated the architecture question to this ADR.

## Evidence

The decision-relevant facts from R1-B0 (`main` at `f944c362`):

- Sample n = 50 items across the 5 consuming domains.
- No-change (identical URL list between variants): **36/50 (72%)**.
- Any change: **14/50 (28%)**.
- 2+ changes: **5/50 (10%)**.
- Coverage bit-identical between variants: **48/48 items ≥ 1 result, 48/48 items with 4 results** under both variants. Semantic contribution never rescues coverage.
- Manual quality classification of the 14 changed cases:
  - Clear rescues (semantic pick better): **7**
  - Neutral / equivalent: **6**
  - Clear harms (semantic pick worse): **1**
- Rescues outnumber harms 7 : 1.
- Domain effects:
  - **Publications**: 10/10 no-change. Semantic effect zero. Rich canonical metadata dominates.
  - **Presentations**: 10/10 no-change. Semantic effect zero.
  - **Media**: 4/10 no-change (6 changed). 30 % clear rescue rate.
  - **Blog**: 7/10 no-change (3 changed). ~10 % clear rescue rate.
  - **Writings**: 5/10 no-change (5 changed). 30 % clear rescue rate.
- Rescues capture same-era temporal clustering and sub-topic sub-family that current canonical categorization does not encode.
- The only currently-unused canonical relationship (`sivuyhteys`, 75/218 Presentations) does not cover the Media/Blog/Writings surfaces where rescues occur.

Interpretation: semantic similarity does not provide canonical truth and does not rescue coverage. It currently improves ranking quality on already-established candidate pools on Media / Blog / Writings surfaces in a way that would be visible to users after removal.

## Decision

**Retain the existing pre-closure semantic layer (`src/_data/semanticRelated.json` + `scripts/build-semantic-related.js` + the semantic branch in `computeRelatedContent`) as bounded auxiliary ranking infrastructure.**

The semantic layer is NOT:

- canonical content
- canonical metadata
- taxonomy
- `contexts` membership
- Research membership
- identity authority
- URL authority
- source / landing authority
- a public knowledge graph
- a primary content-relationship model

Its role is strictly:

> optional additive ranking support over an already-established candidate pool.

Canonical metadata and explicit canonical relationships remain the authoritative signals. The semantic contribution is retained because R1-B0 measured a real user-visible quality advantage on three consuming domains that removal would degrade.

**New embedding- or LLM-derived infrastructure is not authorized by this ADR.** ADR1 classifies existing pre-closure infrastructure; it does not license expansion.

## Canonical authority boundary

The R1 hard-boundary line from the 2026-08-20 roadmap is replaced with a more precise formulation. The old line was:

> no embedding / LLM recommender

The precise boundary going forward is:

> No embedding- or LLM-derived signal may define canonical identity, taxonomy, `contexts`, Research membership, source/landing semantics, content ownership, or candidate eligibility. Existing pre-closure semantic similarity may remain as bounded auxiliary ranking infrastructure where measured user value exists, provided canonical candidates and destinations remain authoritative.

And:

> New embedding/LLM infrastructure is not authorized by this decision. Any change that would add or extend embedding/LLM infrastructure requires a separate architecture decision backed by new measurement evidence.

## Permitted semantic role

Under this ADR the semantic layer may:

- contribute an additive ranking boost to `computeRelatedContent` on the same candidate pool that canonical metadata scoring evaluates
- retain its current `SEM_WEIGHT = 5` and `SEM_MIN = 0.6` thresholds
- retain its current per-anchor top-K structure (`src/_data/semanticRelated.json`)
- be regenerated periodically from the existing embedding cache using `scripts/build-semantic-related.js` when canonical URL churn crosses a documented staleness threshold
- reorder within the top-N cutoff that canonical scoring already produced

## Prohibited semantic roles

Under this ADR the semantic layer may NOT:

- define canonical identity
- define taxonomy
- infer `contexts`
- determine Research membership
- override source, landing, or content ownership
- decide which items are eligible to appear at all (eligibility remains canonical: `score > 0` from metadata OR `semanticBoost > 0` for items in the same candidate pool)
- create new canonical items
- be exposed as a public knowledge-graph JSON contract
- drive user-visible relationship claims that are not derivable from canonical content
- introduce a client-side parallel content model
- introduce browser-side embedding calculation
- introduce runtime model inference or runtime vector search
- introduce online / LLM-derived ranking

## Candidate eligibility

Candidate eligibility is canonical-only. The pool from which related items are drawn is built from the existing content collections iterated by `computeRelatedContent`. The semantic layer influences ordering within that pool. It does not admit new candidates that would otherwise be ineligible.

Formal model:

```text
canonical content
  → shared Eleventy collections (uniqueContentItems in computeRelatedContent)
  → candidate pool (deterministic, canonical-derived, identity by canonical URL)
  → per-item score = metadataScore + (sim >= SEM_MIN ? sim * SEM_WEIGHT : 0)
  → deterministic sort (score desc, date-desc tie-break)
  → limit (default 4)
  → Nunjucks SSR
  → canonical landing destination
```

Semantic similarity affects the `sim` term and therefore the sort order within the already-canonical pool. It does not create the pool, does not create identities, does not create URLs, does not create landings.

## SSR / runtime boundary

Related content remains build-time / SSR-first. The semantic layer must not introduce:

- browser-side embedding calculation
- runtime model inference
- runtime vector search
- a client-side parallel content model
- runtime JSON → HTML relationship rendering

Current architecture, unchanged by this ADR:

```text
canonical content
  → Eleventy build-time computation (computeRelatedContent)
  → Nunjucks / SSR (content-context-sidebar.njk)
  → canonical links
```

## Domain evidence

R1-B0's measurement shows the semantic effect is domain-dependent:

| Domain | Semantic effect observed | Rationale |
| --- | --- | --- |
| Publications | Zero (10/10 no-change) | Rich canonical metadata (100% categories, 98% contexts, 96% keywords per R1-A) already dominates. |
| Presentations | Zero (10/10 no-change) | Canonical metadata + `sivuyhteys` potential already suffice on this sample. |
| Media | Material (30 % clear rescue rate) | Sub-topic sub-families (open-science, AI-education, local-Jääli) that canonical categories do not partition. |
| Blog | Modest (10 % clear rescue rate) | Same-era temporal + local clusters. |
| Writings | Material (30 % clear rescue rate) | Regional-strategic and school-network sub-topics. |

This ADR retains **one** shared ranking mechanism even where the weight has no visible effect on Publications and Presentations. The one-mechanism rule prevents per-domain ranking bifurcation.

## R1-B1 consequence

**R1-B1 is UNBLOCKED after this ADR is merged.**

Justification:

- The semantic layer is now explicitly classified as permitted auxiliary ranking infrastructure.
- Candidate identity remains canonical.
- Thesis canonical metadata coverage is strong (100 % contexts, 90 % categories, 71 % keywords per R1-A).
- No new semantic infrastructure is introduced by R1-B1.
- No new canonical field is introduced by R1-B1.
- Rendering remains SSR — a single `{% include "content-context-sidebar.njk" %}` in `src/opinnaytteet/thesis-details.njk`, matching `publication-item-body.njk:122`.
- Existing shared related-content machinery is reused as-is.

Explicit R1-B1 non-modification rule:

> R1-B1 must not modify semantic scoring, must not generate new embeddings, must not change `SEM_WEIGHT` or `SEM_MIN`, and must not redesign related-content ranking. R1-B1 is a surface-convergence slice only.

The R1-B1 specification in `docs/r1a-canonical-related-content-suitability-audit-2026-08-29.md` §"R1-B1 — deferred, BLOCKED on R1-B0" applies verbatim. The only condition that changes with ADR1 is the block-lift.

## Future change triggers

Any of the following changes requires a **new architecture decision backed by new measurement evidence**, not ADR1's authority:

- change embedding model
- regenerate the semantic representation in a materially different way
- change `SEM_MIN`
- materially change `SEM_WEIGHT`
- add new semantic consumers outside the current `relatedContent` filter
- change candidate eligibility
- introduce runtime inference
- expose semantic graph / data as a public contract

Small maintenance of the retained current mechanism (periodic regeneration of `src/_data/semanticRelated.json` from the existing embedding cache when URL churn exceeds ~10 %; occasional cache-clear + rebuild for stale entries) does not automatically reopen AC1 and does not require a new ADR. Maintenance means preserving the current behavior, not extending it.

## Deletion / convergence implications

The semantic layer is **retained**. `src/_data/semanticRelated.json`, `scripts/build-semantic-related.js`, and the `SEM_WEIGHT`/`SEM_MIN` branch in `computeRelatedContent` are NOT deletion candidates on current evidence.

Later deletion would become appropriate only if new measurement evidence shows any of:

- canonical metadata improves enough to make the semantic boost redundant on Media / Blog / Writings
- the semantic layer becomes stale or unmaintainable to a degree that measurably harms quality
- its user-value advantage disappears in a re-measurement pass
- another canonical signal fully replaces it

Any such deletion requires a fresh R1-B0-style re-measurement before the deletion PR is scheduled. ADR1 does not pre-authorize deletion.

Unrelated legacy `src/_includes/related-presentations.njk` remains outside ADR1's scope. **Correction (2026-08-30):** ADR1 (like R1-A) originally referred to this partial as an "orphan"; a later post-closure audit found it was in fact a live FI-only consumer on `src/fi/yritys.md`. RP-CONVERGE-01 (2026-08-30) converged that legacy path onto the canonical `presentationContextGroups` projection and deleted the partial. See `docs/rp-converge-01-company-presentations-convergence-2026-08-30.md`. ADR1's substantive conclusions on the semantic layer are unchanged.

## AC1 status

**This decision does NOT reopen Architecture Closure 1.0.**

Justification, per the AC1 reopen conditions in `docs/architecture-closure-1-0-closure-2026-08-29.md` §6:

- **No canonical ownership moves to semantic infrastructure.** Canonical URLs, identity, taxonomy, contexts, source/landing all remain in the Eleventy build model + templates.
- **No parallel client-side content model is introduced.** The semantic layer is build-time-only; the client never sees it.
- **Pagefind does not become canonical.** Pagefind is unchanged by this ADR.
- **Canonical Content v1 is unchanged.**
- **Existing pre-closure infrastructure is being classified, not replaced.** The layer and its behavior are exactly as they were before AC1 closed.
- **Source / landing / context semantics remain unchanged.**

Architecture Closure 1.0 remains `CLOSED / GREEN / MAIN`. `architecture-closure-1-0` tag → `41b88d25` remains authoritative for the closure record.
