## Symptom

`tests/esitykset-no-duplicate-cards.spec.js` was added in PR #250 to
prevent `/esitykset/` from re-introducing duplicate archive cards for
the same canonical presentation URL. The spec is merged to `main` at
commit `b21cf6a9` and passes locally. In practice, however:

1. It is not invoked by any GitHub Actions workflow.
2. It is not invoked by any `npm run …` script.
3. Its `KNOWN_FAILURES` allowlist was compiled from a cache-only build
   whose `_site/esitykset/index.html` is missing about 136 cards that
   the live production build renders — including two duplicated
   YouTube-playlist URLs that would fall through the spec even if the
   spec did run against a live-data build.

## Root cause (as known)

### 1. CI gap — no workflow references this spec

Enumerated `.github/workflows/*.yml`:

| Workflow | Playwright invocation |
| --- | --- |
| `staging.yml` (PR gate) | `npx playwright test tests/accessibility.spec.js tests/navigation.spec.js tests/contrast.spec.js --grep "@smoke"` |
| `weekly-playwright.yml` (scheduled on `main`) | `npx playwright test tests/accessibility.spec.js tests/navigation.spec.js tests/contrast.spec.js` |
| `build.yml` | No Playwright invocation. |
| `audit-fix.yml` | No Playwright invocation. |

Both Playwright-running workflows name three spec files explicitly.
Neither uses a glob. `tests/esitykset-no-duplicate-cards.spec.js` is
not in either list.

### 2. npm-script gap — no script covers this spec either

From `package.json` (Playwright-related scripts):

- `test:a11y` — `npm run build:a11y && PLAYWRIGHT_USE_STATIC_SERVER=true PLAYWRIGHT_A11Y_OFFLINE=true DISABLE_OG_IMAGES=true npx playwright test tests/accessibility.spec.js tests/navigation.spec.js tests/contrast.spec.js`
- `test:a11y:list` — the same three spec files with `--list`.

Both scripts name the same three files explicitly. There is no
`test:playwright`, no glob-form `npx playwright test tests/*.spec.js`,
and no other entry point. The only way to run the new spec today is a
direct `npx playwright test tests/esitykset-no-duplicate-cards.spec.js`
invocation.

**Consequence for a future fix:** effective automated regression
coverage requires **both** a new npm script (that names the spec or
uses a glob covering it) **and** a workflow change (that invokes
that script or the spec). Only one of the two is not enough — a new
script that no workflow calls, or a workflow that references a
non-existent script, both leave the guard silent.

### 3. Test data gap — allowlist compiled from cache-only build

The `KNOWN_FAILURES` list in `tests/esitykset-no-duplicate-cards.spec.js`
was compiled from a BEFORE-snapshot generated by `npm run build:local`,
which resolves to `CACHE_ONLY=true DISABLE_OG_IMAGES=true npm run eleventy:quiet`.
`CACHE_ONLY=true` prevents live API fetches, so items produced by
`data.youtube.*`, `data.finnaAoe.*` and other live-fetch sources do
not enter `pageModel.items` at snapshot time. Duplicates that only
appear in those source families were therefore invisible during
allowlist assembly.

**A live-data build path already exists in the repo.** `package.json`
defines `build:a11y` as `PLAYWRIGHT_A11Y_OFFLINE=true DISABLE_OG_IMAGES=true npm run build:no-og`,
which in turn resolves to `DISABLE_OG_IMAGES=true npm run eleventy` — a
full Eleventy build without `CACHE_ONLY`. It is the same build path
`weekly-playwright.yml` uses. Choosing cache-only for the allowlist
snapshot was an author decision made during PR #250 review, not a
repo-level constraint.

### 4. Spec filter gap — external URLs are excluded

The spec contains:

```javascript
if (!url.startsWith("/presentations/")) continue; // ignore external cards
```

External archive cards (Canva shortlinks, YouTube playlist URLs, etc.)
are skipped before duplicate detection. Even if the spec ran against a
live-data build, duplicates whose card URL is not a local
`/presentations/…/` path would not be counted.

The two YouTube-playlist URLs are new findings. They appear on live
production only because live builds fetch YouTube data
(`data.youtube.tableRows` / `.videos`) that the cache-only build path
does not populate. The spec would fail to see them for two independent
reasons:

1. **Cache-only source data** — they would not appear in the
   BEFORE-snapshot the allowlist was built from, and would not
   appear in the AFTER-snapshot either.
2. **External-URL filter** — even if a live-data snapshot surfaced
   them and the allowlist were updated, the current
   `if (!url.startsWith("/presentations/"))` guard would still skip
   them at test time.

## What is NOT investigated / NOT changed here

Per the workstream scope, this ticket is a factual record. It does
NOT:

- Add a new npm script (e.g. `test:playwright-esitykset` or a
  glob-form runner).
- Modify any GitHub Actions workflow to invoke the spec.
- Rewrite the spec to use a live-data build path (e.g. switching
  BEFORE-snapshot generation from `npm run build:local` to
  `npm run build:no-og`) or to update `KNOWN_FAILURES` accordingly.
- Broaden the spec's URL filter beyond `/presentations/…`.
- Investigate the root cause of the two YouTube-playlist duplicates
  on live production. That is its own follow-up audit.

## Recommended next workstream (separate from this document)

**CI coverage integration for `esitykset-no-duplicate-cards.spec.js`.**
Must add both an npm script (the spec by filename, or a glob
covering it) AND a workflow entry that invokes that script. Only
one of the two is a silent no-op. Consider whether the spec runs
against the same shared build artifact `staging.yml` produces
(live-data via `build:no-og`) rather than a cache-only build, so
the spec's coverage matches the build the site actually ships.

Until this ships, PR #250's guard remains a passive artifact rather
than active protection.
